================================================================================
GYM TRACKER — PROJECT SUMMARY
Last updated: 2026-04-05
================================================================================

This is a Hebrew-language, RTL, mobile-first Progressive Web App (PWA) for
personal fitness tracking. Users log workouts, nutrition, and bodyweight, and
receive AI-like recommendations driven by a deterministic template engine.

Stack: Next.js 15 (App Router) · React 19 · TypeScript · Supabase · Vercel
No external UI library — all styling via inline CSSProperties / CSS variables.

2. AUTHENTICATION & SESSION
================================================================================

Provider: Supabase (email + password only, no OAuth)

Flow:
  1. User visits / → SessionProvider reads current session from Supabase
  2. Not logged in → redirect to /auth
  3. Logged in, no onboarding → redirect to /onboarding
  4. Logged in + onboarding complete → redirect to /home

Key files:
  src/lib/auth.ts          Thin wrapper: signIn, signUp, signOut, getSession,
                           onAuthStateChange (all delegate to Supabase SDK)

  src/lib/session.tsx      React Context (SessionProvider + useSessionContext).
                           Exposes: isLoading, isOnboardingLoading, session,
                           user, hasOnboarding, refreshOnboarding(), signOut().
                           Caches onboarding status in sessionStorage to avoid
                           redundant DB calls.

  src/components/
    ProtectedPage.tsx      Wrapper for all authenticated routes. Shows spinner
                           while session/onboarding loads; redirects to /auth
                           if no session; redirects to /onboarding if onboarding
                           incomplete (unless allowIncompleteOnboarding=true).
    AuthForm.tsx           Email/password form with sign-in/sign-up mode toggle.

Onboarding completion check (src/lib/onboarding.ts):
  isOnboardingComplete({ user, program }) → requires age + weight + height on
  user profile AND at least one workout day with at least one exercise.

3. PAGES — DETAILED
================================================================================

─── /auth ───────────────────────────────────────────────────────────────────
File: app/auth/page.tsx
Renders AuthForm. On successful auth, SessionProvider detects SIGNED_IN event,
hydrates onboarding status, then redirects to /onboarding or /home.

─── /onboarding ─────────────────────────────────────────────────────────────
File: app/onboarding/page.tsx
Who sees it: new users (no completed onboarding) AND users navigating here
             who want to re-edit initial setup.

Form sections:
  1. Personal data: age, weight, height, gender (chip), experience (chip:
     beginner/intermediate/advanced), goal (chip: bulk/cut/maintain), focus
     areas (comma-separated text)
  2. Workout program: dynamic list of training days; each day has a name and
     a list of exercise rows (exercise name, sets, reps, planned weight)
  3. Sign-out button (red, below submit) — for users who signed in with the
     wrong account

On submit: validates required fields → saveOnboardingData() → refreshOnboarding()
           → router.replace('/home')

The header card (with title) is always visible even during page loading.
The form fields only show after loadOnboardingData() resolves.

─── /home ────────────────────────────────────────────────────────────────────
File: app/home/page.tsx
Main dashboard. Loads in parallel: bodyweight logs, nutrition logs, workout
sessions, user profile, active workout program.

Sections (top to bottom):
  1. Status row: current weight card + protein-today card + calories-today card
  2. Bodyweight entry: date picker + weight input + save button. Highlights
     with accent outline when navigated with ?recovery=weight param.
  3. Bodyweight chart: line chart of weight history (BodyweightChart component)
  4. Box 1 – Daily recommendation: title + body + optional CTA link
  5. Box 2 – Weekly goal: title + body + optional CTA link (uses stable weekly
     snapshot from DB if available, otherwise freshly computed)
  6. Box 3 – Data recovery (only shown if data gaps exist): prompts user to
     fill missing data with a direct link
  7. Data completeness card: score bar (0-100%), top 2 gaps with CTA links

The page wraps its content in <Suspense> (required by Next.js 15 for
useSearchParams in static prerendering).

─── /workout ─────────────────────────────────────────────────────────────────
File: app/workout/page.tsx
Live workout session tracker.

States:
  - "no session" (pre-workout): shows today's program day, exercise list,
    energy level picker, "start workout" button
  - "active session": timer running, exercise checkboxes + inline set logging
    (weight/reps/difficulty per set), add set, reorder exercises (counts
    reorders), exercise instructions (collapsible)
  - "completed": summary view + save button

Set difficulty: easy / good / hard
Energy level: low / normal / high

Recovery UX: when navigated with ?recovery=workout, shows RecoveryBanner and
highlights hero card with accent outline. Dismissed on successful session save.

Wraps content in <Suspense> for Next.js 15 compatibility.

─── /nutrition ───────────────────────────────────────────────────────────────
File: app/nutrition/page.tsx
Free-form text nutritional calculator.

Flow:
  1. User types meals in Hebrew/English (one per line, e.g. "חזה עוף 150 גרם")
  2. On calculate: calls calculateNutritionFromText() (shared engine)
  3. Shows results table: each item with name, calories, protein, carbs, fat,
     status (calculated / unresolved)
  4. Shows totals + status message (full/partial/unresolved count)
  5. Save: creates new log for selected date
  6. Append: adds to existing log for that date

Recovery UX: ?recovery=nutrition shows RecoveryBanner, focuses textarea,
dismissed on save.

Wraps content in <Suspense> for Next.js 15 compatibility.

─── /nutrition-history ──────────────────────────────────────────────────────
File: app/nutrition-history/page.tsx
Browse and edit past nutrition logs. List by date descending.
Each entry: expandable with raw text input, macro fields, delete button.
Inline save per entry.

─── /workout-history ────────────────────────────────────────────────────────
File: app/workout-history/page.tsx
Read-only list of saved workout sessions (newest first).
Each entry: date, day name, duration, energy, exercises with sets.
Expandable accordion layout.

─── /profile ────────────────────────────────────────────────────────────────
File: app/profile/page.tsx
Three sections:
  1. Personal profile: age, weight, height, gender, experience, goal,
     focus areas — editable, saves to Supabase profiles table
  2. Theme picker: 6 themes (dark/light/AI/clean/fitness/dashboard) as chips.
     Saved to localStorage.
  3. Workout program editor: same UI as onboarding program section — add/remove
     days and exercise rows, save with replace_active_workout_program RPC.

Recovery UX: ?recovery=program shows RecoveryBanner on program section, accent
outline, dismissed on save.

Sign-out button at bottom.

Wraps content in <Suspense> for Next.js 15 compatibility.

─── /reports ────────────────────────────────────────────────────────────────
File: app/reports/page.tsx
Analytics and charts page. Shows exercise performance trends per exercise,
bodyweight chart, nutrition adherence summary, workout consistency.
Uses ExerciseProgressChart component.

─── /home-v2 ────────────────────────────────────────────────────────────────
Directory: app/home-v2/ (WIP — not yet linked in navigation)
Experimental alternative home layout.

5. BUSINESS LOGIC — src/lib/
================================================================================

─── Goal System ─────────────────────────────────────────────────────────────
goalDefinitions.ts
  GoalType = 'bulk' | 'cut' | 'maintain' | ''
  normalizeGoalType(raw) → GoalType
  Goal definitions include: label, KPI type (weight_up/weight_down/stable),
  preferred weight trend, preferred exercise trend, ideal nutrition status.

─── Progress Status ─────────────────────────────────────────────────────────
progressStatus.ts
  buildProgressStatus({ goal, exerciseNames, workoutHistory, bodyweightLogs,
                         nutritionLogs, profile, workoutConsistency })
  Returns:
    status: 'on_track' | 'partial' | 'off_track' | 'insufficient_data'
    confidence: 'low' | 'medium' | 'high'
    breakdown:
      exercise: { trend, upCount, downCount, validExercisesCount, ... }
      weight: 'up' | 'stable' | 'down' | 'insufficient_data'
      nutrition: adherence result
      consistency: consistency result

getDailyCalorieTarget(profile, bodyweightLogs) → number | null
  Calculates TDEE from weight, height, age, gender, experience level.

getDailyProteinTarget(profile, bodyweightLogs) → number | null
  Calculates protein target based on bodyweight and goal.

─── Exercise Progress ────────────────────────────────────────────────────────
exerciseProgress.ts
  analyzeExerciseProgress(exerciseName, workoutSessions)
  Compares last 2-4 sessions to baseline. Returns:
    trend: 'up' | 'stable' | 'down' | 'insufficient_data'
    confidence: 'low' | 'medium' | 'high'
    lastValue, baselineValue, percentChange

─── Workout Consistency ─────────────────────────────────────────────────────
workoutConsistency.ts
  calculateWorkoutConsistency(workoutProgram, workoutSessions)
  Returns:
    weeklyTarget: number (days per week in program)
    currentWeek: { completed, target, paceStatus }
    lastWeek: { completed, target }
    status: 'ahead' | 'on_track' | 'behind' | 'insufficient_data'

─── Nutrition Adherence ─────────────────────────────────────────────────────
nutritionAdherence.ts
  calculateNutritionAdherence({ goal, nutritionLogs, profile, bodyweightLogs })
  Analyzes last 7 days of logs vs. calorie + protein targets.
  Returns:
    status: 'good' | 'partial' | 'poor' | 'insufficient_data'
    loggedDays, targetCalories, targetProtein, avgCalories, avgProtein

─── Training Load ────────────────────────────────────────────────────────────
trainingLoad.ts
  calculateTrainingLoad(workoutSessions)
  Analyzes recent sessions: performance trend, set effort (difficulty),
  energy level, set count vs. planned, session duration.
  Returns:
    status: 'low_load' | 'normal' | 'high_load'
    confidence: 'low' | 'medium' | 'high'

─── Goal KPI Status ─────────────────────────────────────────────────────────
goalKpiStatus.ts
  getGoalKPIStatus({ goal, bodyweightLogs, workoutHistory })
  Evaluates whether the user's KPI is moving in the right direction for
  their goal (e.g., bulk→ weight should go up, cut→ weight should go down).
  Returns:
    status: 'positive' | 'neutral' | 'negative' | 'insufficient_data'

─── Data Completeness ───────────────────────────────────────────────────────
dataCompleteness.ts
  calculateDataCompleteness({ bodyweightLogs, nutritionLogs, workoutSessions,
                               workoutProgram })
  Scores 0-100. Identifies gaps:
    type: 'weight' | 'nutrition' | 'workout'
    severity: 'high' | 'medium'
    message: Hebrew string
    cta: { href, label } (links to recovery page with ?recovery= param)
  Returns:
    score: number
    overallStatus: 'complete' | 'partial' | 'poor'
    gaps: DataGap[]

─── Recommendation Engine ────────────────────────────────────────────────────

recommendationContext.ts
  buildRecommendationContext(input: BuildContextInput) → RecommendationContext
  Combines all computed metrics into one flat context object with ~25 fields:
    goal, goalLabel,
    todayIsWorkoutDay (derived from session history: ≥2 times same DOW in 6wks),
    todayWorkoutDone, todayWorkoutName (next in rotation),
    exerciseTrend, hasDecliningExercise, hasPlateauExercise, hasImprovingExercise,
    exerciseDownCount, exerciseUpCount,
    nutritionStatus, hasTodayNutritionLog,
    weightTrend, goalKpiNegative, hasTodayWeight,
    consistencyRatio, hasConsistencyIssue, weeklyTarget, completedThisWeek,
    lastWeekCompleted, fatigueDetected,
    progressStatusLevel, dataCompletenessScore,
    topGapType, topGapSeverity, hasHighGap

recommendationRenderer.ts
  RecommendationTemplate type:
    id, type ('daily'|'weekly'|'recovery'), enabled, priority: number,
    conditions: { requiresWorkoutDay?, requiresGoal?, requiresNutritionStatus?,
                  requiresWeightTrend?, requiresFatigueDetected?, ... }
    title, body (with {placeholder} substitution), cta?: { href, label }

  RenderedRecommendation = template with variables substituted.
  renderRecommendationTemplate(template, variables) → replaces {key} tokens.

recommendationSelector.ts
  conditionsMatch(conditions, ctx) → boolean (all conditions must pass)
  selectDailyRecommendation(ctx) → RenderedRecommendation (never null,
    falls back to DAILY_FALLBACK)
  selectWeeklyRecommendation(ctx) → RenderedRecommendation (never null,
    falls back to WEEKLY_FALLBACK)
  selectRecoveryRecommendation(ctx, overallStatus) → RenderedRecommendation | null
    Returns null if no gaps. High gaps → high-priority template.
    Medium gaps + non-complete data → medium template.

recommendationTemplates.daily.ts (13 templates + fallback)
  Priority ordering (higher = selected first when conditions match):
    120: daily_workout_day_declining   (today is workout day + declining exercises)
    115: daily_workout_day_plateau     (today is workout day + plateau)
    110: daily_workout_day_fatigue     (today is workout day + fatigue detected)
    105: daily_workout_day_consistency_issue
    100: daily_rest_day_fatigue
     95: daily_workout_day_ready       (today is workout day, no issues)
     90: daily_workout_done_log_nutrition (done workout, missing nutrition)
     88: daily_rest_day_nutrition_issue
     85: daily_cut_nutrition_focus / daily_bulk_weight_not_gaining
     80: daily_workout_done_great
     75: daily_rest_day_log_weight
     65: daily_rest_day_recovery
  Fallback: "המשך לפי התוכנית"

recommendationTemplates.weekly.ts (8 templates + fallback)
    120: weekly_declining_exercise_focus
    115: weekly_plateau_break
    110: weekly_off_track_recovery
    105: weekly_consistency_goal
    100: weekly_cut_nutrition_discipline / weekly_bulk_calorie_surplus
     90: weekly_weight_stabilize
     70: weekly_improving_keep_momentum
  Fallback: "מטרת השבוע: המשך כך"

recommendationTemplates.recovery.ts (6 templates)
  High severity (p100): recovery_high_weight, recovery_high_nutrition,
                         recovery_high_workout
  Medium severity (p60): recovery_medium_weight, recovery_medium_nutrition,
                          recovery_medium_workout
  Each CTA links to appropriate page with ?recovery= param.

weeklyRecommendationEngine.ts
  selectStableWeeklyRecommendation({ goal, recommendationContext,
    progressStatus, nutritionAdherence, goalKpiStatus, workoutConsistency,
    bodyweightLogs, nutritionLogs, workoutSessions })
  Uses 14-day decision window to detect performance signals.
  Produces stable weekly recommendations (avoids day-to-day noise).

weeklyGoalSnapshotService.ts + weeklyGoalSnapshotRepository.ts
  syncCurrentWeeklyGoalSnapshot(...) — saves or updates weekly snapshot in DB.
  Each snapshot: { id, userId, weekStart, templateId, title, body, cta,
                   goal, contextSnapshot }
  On home page: if DB snapshot for current week exists, displays it (stable).
  Otherwise uses freshly computed weekly recommendation.

7. NUTRITION ENGINE — src/engines/
================================================================================

proteinEngine.ts  (shared-engines/proteinEngine path alias)
  calculateNutritionFromText(text: string) → NutritionCalculationResult
  Parses free-form Hebrew/English meal text line by line.
  Handles:
    - Hebrew units: גרם, קילו, כף, כוס, פרוסה, יחידה, ...
    - Hebrew quantity words: חצי, שלוש, ארבע, עשר, מאה, ...
    - Portion sizes embedded in item name
    - Multiple items on one line
    - Fallback: unresolved items counted separately

  NutritionCalculationResult:
    items: NutritionItem[]   (each with name, macros, status, confidence)
    totals: { calories, proteinGrams, carbs, fat }
    unresolvedCount: number
    hasPartialNutrition: boolean

proteinFoods.ts (food database)
  Large list of foods with canonical names and aliases.
  Each entry: { name, aliases[], calories, proteinGrams, carbs, fat }
  Per 100g OR per unit depending on food.

8. DATABASE SCHEMA (Supabase)
================================================================================

All tables are per-user (RLS via user_id = auth.uid()).

profiles
  id (uuid, FK auth.users)
  age, height (number)
  gender ('male'|'female')
  experience ('beginner'|'intermediate'|'advanced')
  goal ('bulk'|'cut'|'maintain')
  focus_areas (text[])
  updated_at

bodyweight_logs
  user_id, log_date (date) — composite PK
  weight (numeric)

workout_programs
  id (uuid), user_id, name, is_active (bool), updated_at

workout_program_days
  id, program_id, day_order (int), name

workout_program_exercises (rows within a day)
  id, day_id, exercise_order
  exercise_name, sets_planned, reps_heavy, weight_heavy

Custom RPC: replace_active_workout_program(p_name, p_days jsonb)
  Atomically deactivates old program, creates new one with days & exercises.

workout_sessions
  id, user_id, session_date (date), day_id, day_name
  started_at, ended_at, duration_seconds
  energy_level ('low'|'normal'|'high')
  reorder_count (int)

workout_session_exercises
  id, session_id, exercise_name
  planned_sets, planned_reps, planned_weight
  completed (bool), duration_seconds

workout_session_sets
  id, exercise_id, set_order (int)
  weight, reps, difficulty ('easy'|'good'|'hard')

nutrition_logs
  user_id, log_date (date) — composite PK
  raw_input_text (text)
  total_protein_grams, total_calories, total_carbs, total_fat (numeric)

nutrition_log_items
  id, log_id (FK), item_order (int)
  original_text, display_name
  protein_grams, calories, carbs_grams, fat_grams
  status ('calculated'|'unresolved')
  reason (text, nullable)

weekly_goal_snapshots
  id (uuid), user_id
  week_start (date) — Monday of the ISO week
  template_id, title, body
  cta_href, cta_label
  goal, context_snapshot (jsonb)
  created_at, updated_at

12. KEY ARCHITECTURAL DECISIONS & PATTERNS
================================================================================

1. ALL STYLES INLINE
   No CSS modules, no Tailwind. Every style is either inline CSSProperties or
   a CSS variable reference. This means components are self-contained but
   cannot be tree-shaken. Pattern: const fooStyle: CSSProperties = { ... }
   at the bottom of each file.

2. REPOSITORY PATTERN
   Every Supabase call goes through a repository function in src/lib/repositories/.
   Pages never call Supabase directly.
   Repositories are thin async functions returning typed objects.

3. DETERMINISTIC RECOMMENDATION ENGINE
   No LLM / free-text generation. All recommendation text is pre-written in
   template files. Templates have conditions (boolean checks against context)
   and priority scores. The selector picks the highest-priority matching template.
   Variables ({placeholder}) are substituted at render time.

4. COMPUTED METRICS AS INPUTS
   Home page computes ~8 derived metrics (progressStatus, nutritionAdherence,
   trainingLoad, etc.) via useMemo chains before building the recommendation
   context. This ensures all analytics logic is isolated and testable.

5. DATA CONFIDENCE LEVELS
   Every computed metric returns a confidence level (low/medium/high) based on
   how much data is available. Recommendations suppress themselves when confidence
   is too low, triggering recovery recommendations instead.

6. WEEKLY SNAPSHOT PERSISTENCE
   Weekly recommendations are computed fresh on every render but ALSO written
   to a Supabase table (weekly_goal_snapshots). The home page displays the
   SAVED snapshot for the current week if one exists, ensuring the weekly goal
   doesn't change mid-week due to fluctuating data.

7. SUSPENSE WRAPPING (Next.js 15 requirement)
   All pages that use useSearchParams() must be wrapped in <Suspense> for
   static prerendering. Pattern: rename default export to XxxPageContent(),
   add new export default XxxPage() { return <Suspense><XxxPageContent/></Suspense> }
   Affected pages: home, workout, profile, nutrition.

8. RTL HEBREW THROUGHOUT
   html dir="rtl". All text, labels, and messages are in Hebrew.
   Flex layout is naturally RTL (start = right, end = left).
   Food parser handles Hebrew units and number words.

9. RECOVERY UX PATTERN
   The ?recovery= query param creates a cross-page UX flow. Data gap detected
   on home → CTA with ?recovery=xxx → target page shows banner + highlight.
   User completes action → banner dismisses (recoveryDismissed state).
